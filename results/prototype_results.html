Does more stable clustering improve GraphRAG answers?

Prototype results. HotpotQA dev (distractor), 20 questions, 200 Wikipedia paragraphs, 1,120 scored answers. Local qwen3:8b on an RTX 4060.

The prototype runs the full pipeline: build a knowledge graph, cluster it three ways, remove edges, then measure graph stability, evidence retrieval and answer quality.

Note on sample size. With 20 questions, one question moves exact match by 5 points, so gaps of 1–2 questions are noise. The prototype shows the pipeline works; it cannot yet say which clustering method is better.

Key findings

  1. Edge removal does not break multi-hop bridges. The two gold paragraphs stay linked in every condition (70% of questions for the LLM graph, 100% for the NLP graph). In HotpotQA they are almost always joined by one entity named in both, not by a graph path.
  2. Evidence retrieval barely moves. Supporting-fact recall changes by at most 1.6 points under critical-edge removal for local search.
  3. Community summaries can carry facts the graph lost. Global search answered 5 questions that dense retrieval missed, including one whose graph link was broken.
  4. Leiden's own randomness is large. Two Leiden runs on the same unchanged NLP graph agree only at ARI 0.88, close to the effect of removing edges (0.79).

What was compared

  • Graph: LLM-extracted (with entity merging), NLP noun-phrase.
  • Clustering: Leiden, Louvain, k-core hierarchy.
  • Condition: clean; 5% random edge removal (2 repeats); top-5% edges by betweenness ("critical").
  • Retrieval: local, routed, global; baselines BM25 and dense.

Same answer model, prompt and evidence budget (10 sentences plus up to 3 community summaries) everywhere. Global search runs on the clean graph only.

Examples

  • Critical-edge removal changed the answer. Song written by Johnny Russell: gold "Buck Owens"; clean graph "Buck Owens"; after critical removal "The Beatles" (local, NLP graph, Leiden).
  • Critical-edge removal changed the answer. George Reed's teammate: gold "Johnny D. Bright"; clean graph "Johnny Bright"; after critical removal "Damon Allen" (local, LLM graph, Leiden).
  • A community summary rescued a broken graph link. Developer of the 41st Tactical Squadron's jets: gold "the Mikoyan design bureau"; global search "Mikoyan design bureau". The LLM spelled the plane "MIKODYAN MIG-29", so no graph path existed.
  • All evidence found, answer still wrong. Chamberlain of the Merrie Monarch: gold "Colonel Charles Hastings Judd"; predicted "George W. Macfarlane". The 8B answer model is a bottleneck.

Questions for the full study

  1. Damage entity–paragraph links too? Removing graph edges alone cannot break HotpotQA bridges, so the perturbation may need to cover missing mentions as well.
  2. Keep entity merging in the method? It fixes naming drift (4 hand-checked merges here), but it is a step standard GraphRAG does not have.
  3. Use a stronger answer model? The 8B model often answers wrongly with all gold evidence in hand.
  4. Scale to 500 questions. Build the LLM graph on free cloud GPUs or a few dollars of paid API; everything else runs locally.
